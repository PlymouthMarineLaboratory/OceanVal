      OceanVal has just identified whether the units are the same or whether the observational data needs to be adjusted to be in the model units. Please check the unit conversions below before proceeding.

      Each observation becomes observation × Multiply by + Add before it is compared with the model. Multiply by rescales the units: roughly 1.025 turns µmol/kg into mmol/m3. Add shifts the zero point: 273.15 turns °C into K. Leave both boxes empty when no conversion is needed, and fill in any row OceanVal could not work out. Its suggestions are in red and bold.                 Looking at the files' times

                OceanVal is checking whether the times of the files are the start or the end of the period each mean covers.

                OceanVal reads the dates of each variable's files in each simulation, to find any gaps in them. The simulations are compared over the years they all have.

                The simulations can be on different model grids. To compare them cell by cell, and to take means over exactly the same area, they need to be put on one grid.

                Do you need to unify the model grids? Required

                Cells with no value in any one simulation are made missing in all of them. Once the simulations are on one grid, a cell that is missing in one simulation (land, say, or a place it has no water) is set to missing in every simulation, so that all of them are compared over exactly the same cells. This is judged from the first time step of each simulation's output, for each variable and each layer.

                How should they be put on one grid? Required

                A lon/lat box and resolution

                Every simulation is put on a regular lon-lat grid of this box and resolution, with nctoolkit's to_latlon.

                The grid of a baseline simulation

                The baseline's grid is the one the comparisons are made on. Each of the other simulations is regridded to it, with nctoolkit's regrid. The baseline itself is not regridded.

                How does OceanVal identify simulation files to matchup?
                
    
                
    
                
      
                Where it looks. OceanVal searches the directory you give, and the number of directories below it that you say, for netCDF files. Once you have told it the names of your simulation variables, it works out which files contain each one.
                
      
                Which files it uses. Where a variable is held at more than one time resolution, for example in both daily and monthly files, OceanVal uses the files with the highest temporal resolution, so your matchups are as detailed as your output allows.
                
      
                When to help it. A simulation directory often holds files that are not the output you want to validate: restart files, test runs, 5-day means, or files for a spatial subregion beside files for the whole domain. If these are picked up, the matchups can be wrong. Don’t worry, OceanVal will tell you exactly what files it’s going to use for matchups later on. Put words from the names of the files to leave out in Skip file names containing (for example restart 5d), or words that the files you want share in Only include file names containing (for example grid_T).
                
      
                Only file names are checked, not directory names. To choose words, look at the names of the files in your simulation with “Click here to view the files”.

                Transects
                
    
                
    
                
      
                The model's values along straight lines. Each variable has transects of its own: tick the variables to work transects out for, add as many transects as you like to each, and choose what to work out along each one, and the years of each.
                
      
                Marked in red is what has to be given: at least one variable ticked; for each transect, where it starts and ends, at least one Climatology or Changes, in the Surface or the Vertical, and the years of each of them.
                
      
                
      
                Each transect must run north–south, with the same longitude at both ends, or east–west, with the same latitude at both ends. The Surface and the Vertical (a section through the water column) each have a Climatology, the mean of each month of the year along the line (at the surface) or the annual mean (in the section), and Changes, how it changed over the years, with an optional rolling mean.
                
      
                
        
        
                
        
                
        
        
                A vertical section needs to know where each cell is. With z_level the model's levels are the depths. With a thickness, each cell is placed at its depth, from the top of the water column, and the section is put on evenly spaced depths.
