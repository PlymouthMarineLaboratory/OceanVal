The OceanVal app

Validate a simulation from a browser window, with no Python.

The OceanVal app lets you validate a simulation without writing any Python. Run oceanval in a terminal and a page opens in your web browser that takes you from a folder of model output to a validation report: you choose what to do, point it at your simulation, choose the observations to validate against, check the units, and watch the run.

Start it

oceanval only runs from a conda environment that has OceanVal installed (see Installing), as it needs the R packages, cdo and nco that conda provides. In a terminal, activate that environment, then run oceanval in the directory to work in:

bash 
conda activate foo
oceanval

Replace foo with the name of your own environment. If the command is not found, the environment is not active, or OceanVal is not installed in it. OceanVal and python -m oceanval do the same. Matchups, scripts and reports are written in that directory unless you choose another, so make a new directory for each simulation.

On a remote machine

If oceanval cannot open a browser for you, it prints a link to open. VS Code forwards its port for you. Over plain SSH, for example from a Windows terminal, it prints the command that forwards the port, such as ssh -L 8765:127.0.0.1:8765 you@server: run it in a new terminal on your own computer (PowerShell on Windows 10 or later has ssh), leave it open, and open the link in your browser. When it prints that command, oceanval uses port 8765 if it is free, so the command is the same every time; choose another port with --port. When it opens the browser itself, as in VS Code, it uses any free port. The printed login is a guess: use the one you normally connect with. The run carries on if you close the page, and you can come back to it with the same link.

Keeping the data downloaded

The built-in observational datasets are downloaded every time a matchup needs them, and their servers can be slow or out of reach. To keep what is downloaded for later matchups, open Preferences (the cog beside the OceanVal name) and give a folder for the data store. The folder must already exist: OceanVal keeps everything in an oceanval_datastore folder it makes inside it, and never writes or removes anything outside that. Choose a disk with a reasonable amount of free space, as the store grows as more data is kept in it and can come to several GB. Leave the folder empty to keep nothing.

Choose how matchups use it:

  • Always use data from your data store, if available: what is in the store is used, and only what is not is downloaded, and kept.
  • Only use the data store when download fails: everything is downloaded each time, as without a store, and kept, replacing the copy in the store. The copy is used only for what cannot be downloaded, and the run says so. A server that is slow, rather than one that fails, is waited for.

Only OceanVal’s own datasets are kept (WOA23, OC-CCI, NSBC, COBE2, GLODAP and ICES), never data of yours. What OceanVal downloads is the area and years a matchup needs, so the store keeps track of them: gridded data is kept for the model’s area, rounded out to whole degrees (or the whole globe, for a model covering 90% of it), and ICES data a year at a time for the area asked for. A later matchup whose area and years are inside what is kept takes it from the store; a wider area is downloaded again, and replaces what was kept with data covering both. Something downloaded earlier in the same run is never downloaded again, so the ICES bottle data every ICES nutrient comes from is downloaded once. What is kept is used however old it is, and the run says when it was downloaded; this year’s COBE2 data, still being added to, is not kept. The setting is used by every matchup, including those run from Python; oceanval.matchup(..., data_store=False) leaves it out for one run.

Running the output from Python

The window does nothing you could not do in Python. It writes the matchup script first, to matchup.py unless you choose another name, and then runs it. The script holds your own data, every recipe (those you did not tick are commented out), the conversions, the oceanval.matchup() call and, for a matchup and validate run, the oceanval.validate() call, so you can read it, edit it and run it again later with python matchup.py.
