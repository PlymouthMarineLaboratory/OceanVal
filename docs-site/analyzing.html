Analyzing simulations

Climatologies, time series and transects of one simulation, or of several side by side, with no observations.

On this page
  • Analyze simulations
  • Compare simulations

Two of the app’s boxes work on model output alone, with no observations: Analyze simulations for one simulation and Compare simulations for two to five side by side. Each builds an HTML report laid out like a validation report, and writes the Python script it ran, so the analysis can be repeated.

Analyze simulations

Run oceanval, choose Analyze simulations, and the app takes you through these pages, each with Back, which keeps what you entered:

  1. Simulation: where the output is, as for a validation but with no domain to choose.
  2. Variables: a row for each, with the name in the simulation (clicking opens a searchable list of the model’s variables; several can be summed as a+b). Nothing is ticked to start with.
  3. The files holding each variable, their time resolution and dates, with any missing ones reported.
  4. The analyses: Map climatologies, Map phenologies, Long-term time series, Seasonal cycles, Map temporal changes and Analyse transects. Each opens a pop-out with a row for each variable, where you tick it, give its years and choose surface, bottom or water column; an i beside each option says what it plots.
  5. Cores, missing values and figure code: how many cores OceanVal may use, what counts as missing, and whether the report holds code to reproduce each figure.
  6. Where to save: the analysis goes in oceanval_analysis in the directory you choose, replacing any there.

The window then writes the oceanval.analyze() call into analysis.py (or Save Python script to run later writes it without running it) and runs it. A grid shows each variable and analysis as it is worked out, and the report grows a variable at a time, linked from the grid. Full details are in The OceanVal app.

With raw FVCOM output, every analysis can be chosen, at the surface, the bottom or through the water column, whose cell thickness is not asked for, nor that of a transect’s section: it is worked out from the sigma levels, h and zeta, and a note above the analyses says so. The maps are drawn on the FVCOM mesh itself, and the spatial means are weighted by the areas of its cells.

Compare simulations

Compare simulations does everything Analyze does for two to five simulations and shows them side by side in one report: the maps are a panel for each simulation on one colour scale, and the time series have a colour for each simulation. With exactly two simulations, the climatology’s maps also show the difference: the annual mean is drawn for both and as the first simulation minus the second (named above its map), and the monthly maps are a row for each simulation and one for the difference, each named to the right of it. The differences share a colour scale symmetric about zero, and if the simulations are on different grids (and were not unified) the second is regridded to the first’s for the difference only. The pages are:

  1. Which simulations? A name, directory and directories down for each.
  2. Which variables? A row for each, with the model variable that holds it in every simulation, which can differ.
  3. Units, only if a variable is in different units: the first simulation’s units are the comparison’s, and the others are converted with a multiplier and an adder.
  4. The files of each simulation; they are compared over the years all of them have.
  5. Unify the model grids? Optionally put the simulations on one lon/lat grid, or on one simulation’s grid, with a regridding method of your choice. A cell with no value in any one simulation is made missing in all, so they are compared like for like.
  6. Mask part of the domain? Optionally keep only the cells of a netCDF mask you give.
  7. The analyses: the same six as Analyze, then the cores, missing values and figure code.

The results go in oceanval_simulation_comparison, from a script called simulation_comparison.py that calls oceanval.compare_simulations(). See The OceanVal app for every option. To look at one simulation’s fields first, see Viewing simulations.
